# Doctor check catalog

Generated by `sadi-doctor docs`; do not edit.

## PLAT-010 - Supported OS and version

- Layer: plat
- Severity: blocker
- Detection: platform.platform(), /proc/version on WSL
- Failure modes:
  - `unsupported-os`: OS release older than Windows 10 / macOS 12
  - `wsl1`: WSL 1 has no USB path; use WSL 2 or Windows

## PLAT-030 - Locale and encoding

- Layer: plat
- Severity: warning
- Detection: locale.getpreferredencoding(False), sys.flags.utf8_mode, LANG
- Failure modes:
  - `non-utf8-console`: Console encoding is not UTF-8 and UTF-8 mode is off
  - `c-locale`: LANG is C/POSIX or unset

## PLAT-050 - Environment variables that change SADI behaviour

- Layer: plat
- Severity: info
- Detection: SADI_* environment variables
- Failure modes:
  - `failpoints-armed`: SADI_FAILPOINTS is set: the store injects faults on purpose

## EXT-010 - sadi_py imports

- Layer: ext
- Severity: blocker
- Detection: subprocess `python -c 'import sadi_py'` with a 20 s timeout
- Failure modes:

## NET-010 - Loopback works

- Layer: net
- Severity: blocker
- Detection: bind 127.0.0.1:0, connect, echo one byte; getaddrinfo('localhost')
- Failure modes:
  - `no-loopback`: A one-byte TCP round trip on 127.0.0.1 failed
  - `localhost-not-loopback`: localhost resolves to a non-loopback address

## NET-020 - API port available

- Layer: net
- Severity: error
- Detection: bind 127.0.0.1:<port> and release it at once
- Failure modes:
  - `port-in-use-other`: Something already listens on the API port
  - `port-privileged`: Port below 1024 needs elevated rights
  - `bind-denied`: The OS refused the bind (reserved range or policy)

## DATA-010 - Data root resolved and usable

- Layer: data
- Severity: blocker
- Detection: Path.exists, is_dir, os.access(W_OK); nothing is created
- Failure modes:
  - `missing`: The data root does not exist yet (first run)
  - `not-a-directory`: The data root path is a file
  - `not-writable`: The current user cannot write the data root

## DATA-020 - Filesystem is safe for durability

- Layer: data
- Severity: blocker
- Detection: filesystem type of the longest matching mount in /proc/mounts (Linux/WSL)
- Failure modes:
  - `network-fs`: The data root is on a network filesystem
  - `drvfs-9p`: The data root is on a Windows drive seen from WSL
  - `fat-exfat`: The data root is on FAT/exFAT (no reliable flush)

## DATA-030 - Free space

- Layer: data
- Severity: blocker
- Detection: shutil.disk_usage of the nearest existing parent of the data root
- Failure modes:
  - `below-minimum`: Under 2 GiB free: acquisition would refuse to start
  - `low`: Under 10 GiB free

## USB-020 - FTDI device visible to the OS

- Layer: usb
- Severity: error
- Detection: Linux: /sys/bus/usb/devices idVendor 0403; WSL also `usbipd.exe list`
- Failure modes:
  - `no-device`: No FTDI device is enumerated
  - `device-on-windows-side`: WSL: usbipd lists the device but it is not shared
  - `shared-not-attached`: WSL: usbipd shares the device but it is not attached
  - `unknown-ftdi-pid`: An FTDI device with a product id outside the allow list

## USB-050 - Permission to open the serial node

- Layer: usb
- Severity: error
- Detection: os.access on /dev/ttyUSB*, node group, os.getgroups (no open is attempted)
- Failure modes:
  - `not-in-group`: Your user is not in the node's group
  - `node-not-accessible`: You are in the group but the node is still not read/write
