# sadi-proto v3.41 codec (optional)
Status: draft

Owner: ticket ~2GGPZ5K. Source: `crates/sadi-proto/src/v3/`. Secondary
target (protocol.md section 8); items 9-11 of section 10 stay unverified.
Compiled only with `--features v3`; not part of the default build and not
used by `Session`.

## Framing
`55 <opcode> <payload..> <crc_hi> <crc_lo>`; length is fixed per opcode.
`v3::crc16` is CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF, no
reflection, no xorout; check value 0x29B1 for "123456789"), stored
big-endian over all preceding bytes including the sync byte.

## Commands
`v3::Command::{RequestReady 0x94, Reset 0xF3, Start 0xF4, Stop 0xF5,
PredefInit 0x93}`. `encode` returns the sealed frame, `decode` is the
inverse. PredefInit carries loop frequency (u16 LE), `InitMode`
(2 pendulum, 3 MOM, u16 LE) and four `VendorRange` codes
({0..=5, 9..=12}). 0x92, 0x90 and 0x63 are not implemented (0x92 is
ignored by the firmware).

## Packets
`v3::Packet::decode` checks sync, per-opcode length and CRC, then parses
0xF6 version (float32 LE), 0xF2 ack (echoed opcode, status) and 0x61 data
(30 bytes: 4x u16 ADC, encoders i32, capture, velocity, 12-bit inputs,
u32 msg count, all little-endian). Raw bytes become enums through
`TryFrom` (`HostOpcode`, `DeviceOpcode`); unknown values are `V3Error`
variants, never panics.

## Auto-detect probe (sketch, not wired)
The two protocols share the 0x55 sync byte but differ in tail and CRC, so
a host can tell them apart by trying one and listening:

1. Purge, send the v1.003 Query command (62 bytes, tail AA 55 AA 55). If
   a 612-byte type 4 packet arrives within the timeout, the board is v1.
2. Otherwise purge and send the v3 `55 94 2F 78`. If `55 F6 .. crc`
   (8 bytes, valid CRC) arrives, the board is v3.41 and the float32 is the
   firmware version.
3. Neither answers: report "no device" (v3 boards send nothing
   unsolicited, so silence is expected for a wrong probe).

A v3 board may ignore the v1 Query as an unknown frame; a v1 board's
reaction to the v3 bytes is unverified (protocol.md section 10, item 5).
Implementation would live outside `v3` behind the feature and is out of
scope here.
